# 技能包供应链登记处

技能包登记与放行服务：接收包清单、文件摘要、依赖、入口点与能力声明，比较版本差异后按风险路由
到代码审查、数据所有者或财务审批；签署只覆盖确定的内容摘要与能力集合，内容或依赖漂移时自动失效。
租户启用时校验地区、套餐与冲突能力；灰度按确定规则分组，异常率越线冻结新分配并回滚到最近安全版本。

## 核心设计

- **内容指纹（`registry/canonical.py`）**：对规范化后的文件摘要、依赖、入口点和能力集合取 SHA-256。
  同内容必然同摘要，改一个文件摘要或依赖版本即新版本。
- **风险路由（`registry/policy.py`）**：能力 -> 所需审批环节、最低套餐、允许地区、冲突能力组。
  邮件写/支付/家庭设备分别要求数据所有者、财务等额外环节；策略从 `domain/risk_policy.json` 加载。
- **签署（`registry/signing.py`）**：HMAC-SHA256，签名串只含 `{指纹, 能力集合, 环节}`，
  内容漂移导致指纹改变，旧签名在批准时**验签失败**（而非维护“失效状态”）。
- **事件溯源（`registry/store.py` + `registry/projections.py`）**：SQLite 仅追加事件日志是唯一事实源，
  版本/分配/批次/任务状态全部由事件折叠得到。进程重启重新折叠即可恢复，审查停留环节与回滚批次进度天然连续。
- **并发边界**：每条命令在一个 `BEGIN IMMEDIATE` 事务内重读折叠、校验、追加事件；
  `version_uploads` / `official_versions` 唯一约束兜底，重复上传返回既有版本，并发审批只产生一个正式版本。
- **灰度与回滚（`registry/service.py`）**：桶号 `sha256(版本|租户|盐) % 100`，盐在批次开始时固定；
  异常越线发 `rollout.frozen` 停止新分配；回滚退到批次记录的最近安全版本，分批处理、可重复调用、重启续跑。
- **审计**：每次安装都记录版本号、内容指纹与**逐文件摘要**；可随时校验运行内容与登记是否一致，
  隔离/回滚均列出受影响任务。

## 目录

- `registry/`：服务实现（标准库，无第三方依赖）。
  - `canonical.py`：规范化与内容指纹。
  - `policy.py`：风险路由、套餐/地区/冲突约束、灰度桶函数。
  - `signing.py`：覆盖内容摘要与能力集合的审查签署/验签。
  - `store.py`：SQLite 仅追加事件日志、幂等命令表、唯一约束。
  - `projections.py`：事件折叠成版本、租户安装轨迹、任务、回滚批次。
  - `service.py`：全部命令（上传、验清单、路由、签署、批准、隔离、启用、灰度、冻结、回滚、审计查询）。
- `domain/contract.json`：实体、状态、24 类事件和关键业务规则。
- `domain/risk_policy.json`：可被程序加载的能力风险策略（环节、套餐、地区、冲突组）。
- `domain/policies.json`：四条关键政策的文字描述。
- `examples/events.json`：完整生命周期事件样例（上传→验证→审查→批准→灰度→冻结→回滚）。
- `tools/validate_contract.py`：用 Python 标准库和 SQLite 验证领域资料一致性。
- `tools/demo.py`：端到端演示（无外部依赖，`python3 tools/demo.py`）。
- `tests/`：35 个测试，覆盖去重并发、漂移失效、风险路由、准入拒绝、冻结回滚、重启恢复、历史清单校验。

## 构建与测试

```bash
python3 -m compileall -q .
python3 -m unittest discover -t . -s tests -v
python3 tools/validate_contract.py
python3 tools/demo.py
```

所有命令都在项目根目录执行，数据库文件可以是路径（持久化、可重启恢复）或 `:memory:`（测试/演示），
不需要另行启动数据库、缓存或其他服务。密钥库按签署人编号（生产应换非对称签署）。
